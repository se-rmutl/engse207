## แนวคิดหลัก

- Service-Based/Microservices, boundary, API contract, independent deployment และต้นทุนเครือข่าย
- เปรียบเทียบกับ modular monolith รู้จัก timeout และ partial failure
- การแยกบริการไม่ใช่ปลายทางที่ดีกว่าเสมอ

## กิจกรรมในแล็บ

- แยกโมดูลกิจกรรมหนึ่งส่วนด้วยโครงช่วย รักษา flow หลักเดิม
- ปรับการเรียกผ่าน API และทดสอบเมื่อบริการช้าหรือหยุด
- เขียน ADR ฉบับเต็มเรื่องคงโมดูลหรือแยกบริการ โดยใช้ผลที่สังเกตได้ประกอบ

## เสริมพื้นฐาน (30–45 นาทีในเวลาปฏิบัติ)

timeout ด้วย AbortController, การจัดการ error ของ fetch, ทดสอบด้วย HTTP client

## หลักฐานและการประเมิน

- ADR ฉบับเต็มที่สองใน **ARCH-03** และบันทึกผล failure สำหรับ **ARCH-05**
- หลักฐานทดลองใช้ประกอบ A5 และ A7 ภายหลัง

## ศึกษาด้วยตนเอง 5 ชั่วโมง

- อ่าน API contract 1 ชม.
- ทดลองการเชื่อมต่อและ failure 3 ชม.
- ปรับ ADR 1 ชม.
