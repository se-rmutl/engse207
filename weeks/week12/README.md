## แนวคิดหลัก

- synchronous กับ asynchronous
- producer/consumer, event, queue, eventual consistency, duplicate และ retry
- เชื่อมกับความน่าเชื่อถือและความซับซ้อน

## กิจกรรมในแล็บ

- รัน flow `task.status.changed` ไปยังตัวรับเหตุการณ์ที่เตรียมไว้
- เปลี่ยน payload หรือ handler เล็กน้อย ทดลองส่งซ้ำและหยุด consumer
- อธิบายผลต่อข้อมูลและผู้ใช้ เปรียบเทียบกับการเรียก API โดยตรงในระบบเดิม

## หลักฐานและการประเมิน

- ผลทดลอง event หนึ่ง flow และข้อจำกัด แนบ **ARCH-04/05**
- ไม่บังคับรวม broker เป็นส่วนของระบบส่งมอบสุดท้าย

## ศึกษาด้วยตนเอง 5 ชั่วโมง

- อ่านลำดับเหตุการณ์ 1 ชม.
- ทดลอง handler และผลผิดปกติ 2 ชม.
- บันทึกเหตุผลเลือกหรือไม่ใช้ event 2 ชม.
