## แนวคิดหลัก

- ข้อจำกัดเครือข่ายและทรัพยากร อาการ stale state การแจ้งผล retry และความเสี่ยงรายการซ้ำ
- ขอบเขตความเชื่อถือ การตรวจสิทธิ์ฝั่ง server และ JWT ที่มีอยู่
- ไม่ขยายเป็น native mobile หรือวิชา security เต็มชุด

## กิจกรรมในแล็บ

- ใช้เว็บเดิมผ่าน mobile viewport หรืออุปกรณ์จริง และ Network throttling
- ทดลองเครือข่ายช้าหรือขาดการเชื่อมต่อ แก้ error/loading/retry หนึ่งจุด
- ตรวจผู้ไม่มีสิทธิ์ และอธิบาย flow ด้วย Sequence/Dynamic

## หลักฐานและการประเมิน

- ผลปกติ/ผิดปกติ และแผนภาพ flow ที่ปรับแล้วใน **ARCH-02/05** ใช้ประกอบ A7

## ศึกษาด้วยตนเอง 5 ชั่วโมง

- อ่านผลการทดลอง 1 ชม.
- ปรับการจัดการสถานะ 3 ชม.
- บันทึกข้อจำกัดของผู้ใช้มือถือ 1 ชม.
