## แนวคิดหลัก

- architecture evolution, technical debt และการส่งต่อ
- ความสอดคล้องของแบบ โค้ด และการติดตั้ง
- ทบทวนการปรับบริการเมื่อทรัพยากรเปลี่ยน และเหตุผลที่คงหรือเปลี่ยนแบบ

## กิจกรรมในแล็บ

- ปรับหนึ่งจุดจากผลประเมิน ตรวจ clean start จาก README และ Cloud รุ่นฐาน แล้วปรับเอกสาร
- ผู้สอนตรวจ A1b รายคน รวมส่วนที่แต่ละคนร่วม deploy หรือแก้ config บน Cloud
- เก็บรุ่น A5b/A6/A7 พร้อม source ของแผนภาพและหลักฐานทดลอง

## หลักฐานและการประเมิน

- **A1b** 5 · **A5b** 10 · **A6** 10 · **A7** 10 คะแนน
- ใช้ snapshot/tag ชุดเดียว แยกมิติประเมิน ไม่คิดคะแนนซ้ำงานเดิม

## ศึกษาด้วยตนเอง 5 ชั่วโมง

- เก็บรายละเอียดระบบ 2 ชม.
- ทำเอกสารให้ตรงรุ่น 2 ชม.
- เตรียมสาธิตและสรุปภาษาอังกฤษสั้น 1 ชม.
